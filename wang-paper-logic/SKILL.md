# 研究论文的论证逻辑

帮助作者讲清论文的研究问题、核心直觉，以及方法和实验如何回应这个问题。

## 工作顺序

1. 阅读论文、提纲或相关章节，找出研究设定、方法的关键操作、实验发现，以及作者目前最想强调的贡献。
2. 梳理主线：**重要问题 → insight → 实现它的技术路线 → 实验证据**，再检查现有工作的缺口如何引出这个问题。
3. 找出最影响理解的断点，例如问题由方案倒推、多个卖点并列、方法缺少直觉、benchmark 的特点只出现在表格里、实验与主张脱节。
4. 按用户要求诊断、列提纲或直接改写。修改时照顾技术含义、公式、引用和篇幅。
5. 回看标题、引言、方法和实验是否讲述同一条主线。

## 按需阅读

- 梳理核心问题、创新性、主张及反例时，阅读[核心主线](references/storyline.md)。
- 修改引言、benchmark、方法和实验结构时，阅读[章节写法](references/sections.md)。
- 修改语言、前后呼应、连接词，或进行投稿前检查时，阅读[表达与检查](references/style-and-checks.md)。
- 需要写作案例时，阅读[论文示例](references/writing-example.md)。
- 讨论早期反馈、截稿时间或实验与 Codex 任务的取舍时，阅读[研究节奏与工作取舍](references/workflow.md)。

## 输出要求

- 先概括论文的核心主张，再指出最值得修改的逻辑断点。
- 建议对应到具体位置，说明读者会在哪里困惑、怎样修改。先调整结构，再润色句子。
- 将重要主张与论文已有的证据相连；证据不足时，指出需要补充的分析或实验。
- 用户要求改写时提供可直接使用的文本，并让次要贡献自然服务于主线。
